# Polish audit, Phase 0 (2026-10-31, build 2.3.92)

Method: `tests/polish_audit.js` against a throwaway SQLite install (walk.sh + `shot_seed.php`), logged in as the demo gnome "sprout" (made level 20 and admin so every page renders; feature flags `puzzles_open jigsaw_open gifsaw_open catfish_open ppal_open gourmand_open trek_open` on). 55 pages x 4 viewports (phone 412 dark, phone 412 light, tablet 768 light, desktop 1400 light) = 220 page loads. Screenshots are viewport-only and not committed (they are regenerated by the script). Re-run: install a copy, seed it, then `node tests/polish_audit.js BASE OUT`.

Checked automatically: page-level horizontal overflow, elements poking past the viewport, controls under 44 px, buttons/links with no accessible name, images with no `alt`, `h1` count, console errors and 4xx/5xx, `style=` attributes in the live DOM.
**Not checked:** colour contrast, keyboard order and focus rings, screen reader, 200% zoom, MySQL, real devices, pages that need data the seed does not have (trek fights, delves, expeditions in progress, tournaments, empty states), logged-out pages.

## Clean
- No page-level sideways scroll on any of the 55 pages at any of the 4 widths.
- Exactly one `h1` on every page. No unnamed buttons or links. No `<img>` without `alt`.
- No console errors or failed requests (the only 404 was `visit.php` called with no parameters, which is expected).
- Dark and light phone runs show identical layout metrics.
- The `style=` attributes counted in the DOM (`world.php` 1-2, `town.php?view=passport` 13) are not in the served HTML; they come from JavaScript setting `el.style`, which the CSP allows. Not a violation, but worth knowing about when moving widths and positions into classes.
