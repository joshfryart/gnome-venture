## What we are building
"Stat pieces": every gnome automatically OWNS the stat pieces for the tiers their gnome stat points reach (stats: nimble, lore, luck, sense; tiers 0, 10, 15, 20, 25, 30; tier 0 = everyone), and packs them into their deck by choice (like the counter knacks; look at how counter knacks are owned and packed). Spec for the 24 pieces (4 base + 20 shortlisted) is SP/stat24.json (SP = /tmp/claude-0/-home-user-gnome-venture/9aa93f5c-3276-50e6-8156-dea62561b335/scratchpad): name, stat, tier, type, family (knob/hole edge family), tags, rules text, fx clause string where existing clauses suffice, engine_cost (what new code is needed), motif, risk, value rule. Fuller design notes: SP/tiers2-<stat>.json (all 15 pieces per stat, with change_note and ruleset checks) and the first four base pieces above. Numbers: a = 1 + points/5, b = ceil(a/2) where points = the gnome's points in that stat. Shared Luck roll: chance = min(90, 50 + 2 x Luck points) percent, rolled ONCE per firing and cached so a "roll" clause and a "!roll" clause agree.
Owner decisions: packing = own all, pack by choice; Sharp Eye held shows the piece the creature plays after its aim (v1 already shows the aim itself); Hedge Rummage uses the full Luck roll for Pluck (up to 90%, halved on great creatures); Nimble tempo pieces once a fight; no boss immunity for Turn of the Tale / Unpicked Seam style effects.
Safety rails: everything behind a NEW admin setting `pfight_statpieces` (Off / Admins only / Everyone, default Off, same pattern as the other pfight_* settings); with it Off a fight must be byte-for-byte unchanged (the old-fight md5 tests in tests/pfdeck_v1.php must keep passing without re-recording). Current v1 rules (default for new fights): no set-aside or grouping, flipping is free, a piece may go on any fitting cell, one placement a round, one shared Yield bar, the creature's aim is shown, hand redrawn each round. Never design or implement anything those rules make pointless.
