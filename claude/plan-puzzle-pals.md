## 1. A. "Record the individual piece images"
**My reading (recommended)**: make every Advanced piece of every picture *addressable and showable*: piece id = `<pic slug>:<col>-<row>` on the 12x8 grid, box = `(col/12, row/8, 1/12, 1/8)` of the puzzle area (gallery: whole picture; Places: the centre 3:2 crop, same maths as `puzzles.js`). A piece is shown anywhere with one `<span class="ppiece">` whose background is the full picture at `background-size: 1200% 800%` and `background-position` in percent (`image-rendering: pixelated` for `px` pictures). No new files, no GD, one cached image per picture. The piece a pal "comes from" is stored on the pal (`piece` column, e.g. `7-3`), so pal art and the collection book show the real piece.
**Alternative reading** (rejected for now): record which pieces the *player* placed. The engine is client-side; the server only ever sees the drop count, so there is nothing truthful to record without a new engine protocol. Not worth it for a cosmetic feature.
**Slicing to files** (owner's wording taken literally): 1800x1200 -> 96 JPEG 150x150 ~10 KB each = ~1 MB and 96 files per picture; 98 pictures (81 Places + 3 builtin + 14 launch) = ~9,400 files / ~100 MB, growing with every upload; Places pieces would be 34 px blobs. A sprite sheet (12x8 tiles of 64 px = 768x512 PNG, ~60 KB, one file per picture) is the cheap middle. **Recommendation**: CSS crops now (zero files); add `tools/slice_jigsaw_pieces.py` (sprite sheet per picture into `assets/img/jigsaw/pieces/`) only if a later feature needs standalone piece files (share cards, Aseprite work). Decided by default: no slicing in 2.0.88.

## 2. B. Unlock rule and rosters
- **Release** = the gnome's first `done` Advanced (96) solve of a picture, free play or tournament, server-verified (min 38 s, >= 95 drops, single-use token, admin void respected: a voided attempt that already released stays released; log it). One row `ppal_releases (user_id, pic_id)` UNIQUE. Easy and Expert release nothing (Expert: see Joshua's calls). Replaying Advanced: nothing more.
- On release: event box line on the win card ("The magic of the jigsaw is loose! 6 Puzzle Pals from <title> are somewhere about the Hollow."), `notify()`, Almanac entry `ppal:<pic slug>` (optional), the Jigsaw card gets a small "pals 0/6" pip.
- **Roster per picture: 6** = 3 common, 2 uncommon, 1 rare. Rarity sets find odds (60 / 30 / 10 weight), the frame colour and a small stat lift (see 4).
- **Theme**: a Places picture's pals are creatures of that location kind (haven: hearth folk; wonder: sprites; delve: cave beasts; lair: the villain's leftovers) and named after it. Gallery pictures get authored rosters.
- **Authoring**: `includes/data/puzzle_pals.txt`: `pic_slug|key|name|rarity|calling|grit|nimble|hardiness|luck|piece|blurb` (key unique, `piece` = `col-row` on 12x8 = the cell that fills its body, calling one of the 6; new columns `shape` (e.g. `corner-TT`, `inner-TTTT`, `whimsy-fox`) and `knob` (`round|keyhole|peg|tri|double|hook`)). For the 81 Places, rows are **drafted by a generator** (then deduped and reviewed, section 6): `ppal_place_roster($pic)` draws names from `includes/data/puzzle_pal_names.txt` (`kind|first names...` and `kind|epithets...` banks, 40 + 30 per kind) with `crc32(slug)` seeds, so a place always gets the same 6; an authored row for a place slug overrides the generated one. Launch authoring = 17 gallery pictures x 6 = 102 rows (Haiku drafts, Opus checks names against existing NPCs in `npcs`).
- `tools/lint_puzzle_pals.py`: column count, unique keys, picture slug exists (`JIGSAWS`, uploads list passed in, or `pl-` prefix), rarity in set, calling valid, piece in 0-11 x 0-7, stat total band per rarity (common 3-4, uncommon 5, rare 6), no `|` in text, curly apostrophes, name not an existing NPC name. CI runs it.

## 3. C. Spawning (finds) on any page
- **Second lane in `maybe_random_event()`**, not a row in `random_events`: after the normal event roll fails (or regardless, see below), `ppal_maybe_find($u)`: skip if guest, `!ppal_open()`, a pending event or box exists, the page is excluded, or the gnome has no released roster with a missing pal; roll `1 in ppal_chance` (60); own cooldown `ppal_cooldown_minutes` (30) and cap `ppal_daily_max` (4) on new columns `users.ppal_at/ppal_day/ppal_count` (Hollow day, like events). Never two boxes: the lane only runs when the ordinary roll produced nothing. Why a lane: pals must not steal the 3-a-day event cap or dilute the existing weights, and their odds need their own tuning knob. Reused as-is: the box markup, `$_SESSION['event_pending']` with a token, `event.php`, `finish_event()`, admin "test an event" (add a "test a pal find" button beside it).
- **Pick**: pool = pals of this gnome's released pictures weighted by rarity; **missing pals first**: duplicates only when a roster is complete (then the pal "waves": +1 `times`, no reward; see G). Pending payload `['slug' => 'ppal', 'token', 'pal' => key]`; `finish_event()` gains `case 'ppal'` -> `ppal_claim($u, $key, $token)` (INSERT OR IGNORE `ppal_found`, one go only, re-checks release).
- **Excluded pages**: admin (already), onboarding/tour (already), POST (already), `puzzles.php`, `jigsaw.php`, `gifsaw.php`, `puzzlepals.php`, `puzzles_api.php` (no layout anyway), `trek.php` (the stage owns the screen; also keeps finds out of fights), `event.php`. Everything else (garden, town, world, shops, almanac, games...) is fair ground, which is the point.
- **Find card** = the `eventbox waiting` variant with class `ppalfind`: pal sticker (body + its piece), rarity frame, name, "a Puzzle Pal from <picture>", one button "Say hello" (claim) -> box "X joins your Puzzle Pals (4/6 from <picture>)". Decline = leaving the page (token dies like any event).
- **Collection book** `puzzlepals.php` (Puzzles hub card, menu under Games): one section per released picture: thumb, 6 slots: found = sticker + name + rarity + "found <date>" + `times`; missing = silhouette (same sticker, `filter: brightness(0) opacity(.35)`) with "?"; unreleased pictures listed below as "Solve <title> at Advanced to release its pals" (Places only once unlocked). Header: pals found / total released, "Take along" toggles (see D). Roster complete -> picture frame on its Jigsaw card, a shelf badge on the profile (`ppal_badges_html`, beside `puzzle_badges_html`), Almanac line. No Petals (default; call 6).

## 4. D. Equipped pals: passive perks, shown wherever the gnome shows (Joshua, 2026-10-28)
**Decided: P1 passive. No fighting pals, no Treks (standalone stories).** A gnome of **level 15+** can **equip up to 2 pals** ("Take along", `ppal_found.active`, "2 pals + you" = a party of 3 for show). Equipped pals (a) give small passive perks and (b) **appear wherever the gnome's avatar appears**, so equipping is visible and worth doing. Under level 15 pals can be found, collected and viewed but not equipped (greyed note "Take pals along from gnome level 15"). Setting `ppal_party` (default 0) gates equip + perks + display; `ppal_open` gates everything else.
- **Display rule ("if they are equipped, they show when your gnome shows")**: new `gnome_avatar_pals($u, $size)` in `includes/puzzle_pals.php` = `gnome_avatar()` plus the equipped pals' 64 px stickers as small companions beside the feet (size = 0.45 x the gnome's, left and right, a gentle bob via CSS, no JS). `gnome_avatar()` itself is NOT changed, because `trek.php`, `trek_art.php` and `scene.php` regex its inner svg to re-embed it. Use the wrapper at: `gnome.php:47` (home), nav head `layout.php:656` (small: only if size >= 40, 18 px pals), `customise.php:42`, `sinks.php:392`, `town.php:187` (gnome rows: other players' equipped pals show too), the road fight card `layout.php:454` and `adventure.php:251` (as a visual only), profile / visit pages (grep `gnome_avatar` in `profile.php`, `visit.php` when added there), the Stop/Passport header. NOT in Treks (all three trek renderers keep the plain avatar). A pal's sticker is the same PNG as the book; missing art = nothing drawn (never a broken image). Other players see your equipped pals only on pages that show your gnome publicly (profile, visit, gnome lists).
- **Perks** (small, bounded, additive, computed by `ppal_perks($uid)`, cached per request): each pal row has a `perk` kind; value by rarity common 1 / uncommon 2 / rare 3 units. Kinds (default one per calling, overridable per row): **gather** (+1% per unit to the rare-find chance when gathering, cap +6%), **road** (+1 grit/nimble/hardiness per 2 units in road, lair and delve fights only, cap +3), **finder** (+5% per unit to the Puzzle Pal find chance, cap +30%), **tinker** (+1% per unit XP from games, cap +6%), **bloom** (+1% per unit seed-germination luck in the garden, cap +6%), **shine** (cosmetic: a sparkle on the avatar, no number). Two equipped pals with the same kind stack up to the cap. Nothing touches Petals directly, energy, Treks, trading or the Fair/Show contests (contests stay un-buffed).
- **UI**: `puzzlepals.php` book rows get "Take along" / "Send home" (max 2, one click; swapping out the old one is offered) and a "Your party" strip at the top showing you + 2 slots; hover/tap a pal for its perk line ("Brings +2% rare finds"). Perks list on the gnome page ("Pal perks: ...").
- **Options considered and left out**: P2 pals fighting alongside (new party mode in the road combat engine, a combat balance sim, lair/delve rework: large and risky; revisit only if Joshua asks), P3 collect-only (weaker hook).
- **Hook points**: `puzzle_pals.php` (`ppal_perks`, `gnome_avatar_pals`, equip/unequip), the six display call sites above, `gathering.php` rare-find roll (gather perk), `adventure.php`/`combat_math.php` stat read for road perks (one call each), `games.php` XP/`rewards.php` (tinker), garden germination roll (bloom), `events.php` pal find chance (finder).

## 6. F. Art: every pal unique (Joshua, 2026-10-28)
**Decision: ~590 individually designed pals** (98 pictures x 6 = 3 common + 2 uncommon + 1 rare, +6 per future picture). The earlier "8 shared bodies + a piece badge" idea is DROPPED. Each pal has its own picture, designed from two inputs: **the puzzle it comes from** (its theme, palette, creatures and props) and **its rarity** (how elaborate it is).
- **Design brief per pal**, generated by new `tools/pal_briefs.py` from the roster data into `claude/art-briefs/pals/<pic-slug>.md`: picture title and kind (haven / wonder / delve / lair / gallery), the 6 pals with name, rarity, calling, blurb, 3 motif words pulled from the picture's name and description, the picture's 4 dominant colours (read from the image), and the rarity rules below. Joshua generates the art from the briefs (his process) or our pixel kit does (`aseprite-source/scenes-pil/` style; bulk via a script per picture like the Maplewold one).
- **Pals ARE puzzle pieces (Joshua, 2026-10-28): different piece shapes.** Every pal is a living jigsaw piece, and its **shape is its type**. A piece is described by what each of its 4 sides does (flat / tab / blank) plus a knob style; the shape family below gives ~20 distinct silhouettes, so shape alone separates the pals inside a roster and across the game.
| Family | Sides (T=tab out, B=blank in, F=flat) | Shapes | Rarity use |
|---|---|---|---|
| Corner | F F + two others | corner-TT, corner-TB, corner-BB (flat two sides) | common |
| Edge | one F | edge-TTB, edge-TBB, edge-TBT, edge-BTB | common |
| Inner | no F | inner-TTTT "Plus" (4 tabs), inner-BBBB "Ring" (4 blanks, a hole), inner-TBTB (opposite pairs), inner-TTBB (adjacent pairs), inner-TTTB, inner-TBBB | uncommon (Plus, Ring, TTBB), common (rest) |
| Knob style | round knob, keyhole, square peg, triangle, double-knob, hook | applies to any of the above, picked from the picture's mood (a lair = hooks and horns, a haven = round, a wonder = keyhole) | adds variety |
| Whimsy (rare only) | a wooden-puzzle novelty piece cut to the picture's subject: a star, a moon, a fox, a house, a leaf, a boat | 1 per roster, drawn from a per-picture motif list | rare |
| Merged | two or three pieces locked together as one pal (a 2-piece "pair", an L-tromino) | optional super-rare tier if Joshua wants a 4th rarity | later |
- **Roster recipe (6 per picture)**: 3 common = corner + edge + a plain inner; 2 uncommon = two of {Plus, Ring, TTBB} with different knob styles; 1 rare = the Whimsy piece for that picture. No two pals in a roster share a shape+knob. Across 98 pictures shapes repeat, so **uniqueness comes from the whole pal**: shape x knob x **its own fill** x face x accessory.
- **Each pal's fill is a real piece of its own puzzle**: the body is filled with the pixels of one cell of that picture's Advanced grid (the `piece` column, `col-row` on 12x8; a Place's cell is 30 x 30 file px, a gallery picture's 150 x 150), so a pal looks like the bit of the picture it fell out of, and two pals from different pictures never match. This is the "individual piece images recorded" idea made visible: the piece crop is recorded per pal (data column, no files needed to store it; `tools/gen_pal_art.py` renders it).
- **Face and limbs**: eyes (3 styles), a mouth, stubby legs/arms on tabs, plus one **accessory per pal** (hat, scarf, lantern, tiny tool) taken from the picture's brief motifs; the rare Whimsy piece carries a signature accessory and a glow. Rarity beyond the shape: common = flat outline, uncommon = a second colour accent from the picture, rare = glow + sparkle mark. The rarity frame stays CSS.
- **Production (hybrid, so 590 stays feasible)**: `tools/gen_pal_art.py` builds each sticker procedurally from the data row (shape mask from jigsaw edge geometry in 8 shape/knob templates, fill = the picture cell recoloured to the umber/cream Hearthlight outline, face/accessory layers from small hand-drawn overlay sets) = a **draft** for every pal. Joshua (or a Sonnet pass) then **hand-finishes** or replaces each draft (his generated art) per picture wave. Drafts are valid placeholders: red-bordered only for items with no draft, so the art-gated rollout below can ship on drafts if Joshua approves a wave.
- **Art-gated rollout** (this is what makes 590 hand-made pals practical): `ppal_art_ready($pic)` = all 6 PNGs of that picture exist AND are not placeholders (file size/hash differs from the placeholder). A picture whose roster is not art-ready releases nothing (its Jigsaw card shows no pals pip), so pals ship picture by picture as art lands, in waves (suggest 10 pictures a wave). Placeholders exist only for dev and admin preview (admin sees all rosters).
- **Unique names and ideas**: the 81 Places rosters are first *drafted* from the name banks, then must pass `tools/dedupe_puzzle_pals.py` (modelled on `tools/dedupe_stop_acts.py`: no two pals share a name, an epithet or a core idea across all pictures) and a hand review before their art is briefed. No pal ships with a generated-only name.

## 7. G. Anti-abuse and economy
| Risk | Rule |
|---|---|
| Farming by replaying Advanced | release is once per (gnome, picture); later solves do nothing |
| Page-refresh farming | lane needs a 1-in-60 roll AND 30 min cooldown AND 4 finds/day; a refresh loop gains at most 4/day; 1-in-50 `rate_limited` not needed |
| Multiple accounts | nothing crosses accounts: **not tradeable, not giftable, no Petals, no items** (default; call 5) |
| Guests | lane skipped, claims refused, no release rows, tables purged |
| Pay-to-win | nothing is sold; perks are capped small (section 4) and off until reviewed (`ppal_party` = 0) |
| Duplicates as currency | none: a duplicate only bumps `times` (and never fires while a roster is incomplete) |
| Too-fast solves | the existing 400 ms/piece and drops rules decide `done`; a rejected run releases nothing; an admin void after release does not revoke (logged) |
| Event spam | own cap 4/day, only after the ordinary roll missed, never two boxes, quiet pages list |
Expected pace: with 6 per roster and 4 finds/day max at 1 in 60 views, an active gnome (~80 views/day) finds ~1 a day: a roster in about a week, which suits a collectable.
