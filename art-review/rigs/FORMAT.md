# Fight rig format (reverse-engineered, read-only)

Sources: `game/assets/fightrigs.js` (data, GENERATED by `aseprite-source/v3/creature25/gen.lua`), `game/assets/fightengine.js` (`rigFor`, `add`, `validate`), `game/assets/fightarch.js` (motion per body type), `game/assets/fightscene.js` (mount), `tools/fight/smoke.js` (the only test that loads every rig sheet). `art-review/rigs/rigdata.py` parses fightrigs.js the same way the engine does.

## Data
`window.FE_RIGS = { skel: { slug: { part: [parent, a, b, under] } }, rigs: { slug: [skeleton, fw, fh, u, "part,part,...", motionSet] } }`
- `fw x fh`: one frame (px). `u`: px per figure unit (small 1.0, medium 1.2, large 1.5, boss 2.0, crew 1.2).
- The part list is the **sheet column order**. `parent` 0 = a root that stands on its own. `under` 1 = drawn behind its parent's picture.
- `a, b`: pivot in figure units, a = right of centre, b = up from the ground. Frame px pivot (engine): `x = (fw-1)/2 + a*u + .5`, `y = (fh-5) - b*u + .5`. The ground row is `fh-5`.
- `motionSet` names an archetype in fightarch.js (`snake`, `wisp`, `quad.feline`, `snail`, `folk`, `bird`, `frog`, `bug.wasp`, ...). It keys poses (idle, run, attack, hit, dodge, ko, blink, fidgets) by **part id**, and springs (tail, `ant*`, `s[4-6]`, `t*`, `eye*`, leaf/crest/ball/cloud) by id or pattern.

## Sheet `game/assets/img/fight/rig-<slug>.png`
- Size **exactly `fw * nParts` x `fh * 2`**, RGBA PNG (gen.lua saves RGB-mode sprites, Pillow reads RGBA), hard alpha 0/255 in every shipped sheet.
- Column i = part i, a full `fw x fh` frame in the **same frame coordinates for every part** (a part is drawn where it sits in the assembled creature, not cropped). There are no per-part source rects or offsets: the rect of a part is its column.
- **Row 0 = paint, row 1 = ink**: gen.lua writes the 1 px 4-adjacent ring around the part's paint (colour Hearth Pop ink `#2b1c26`); the part named `eyes` has no ink (engine `ink: pid !== 'eyes'`; `eyeL`/`eyeR` do get ink). Paint must leave a 1 px border free or the ring is clipped.
- Creatures are drawn **facing right**; the foe is mirrored (`scaleX(-1)`) on stage.
- Scale: `PXC = 1/32` board cells per frame px for every rig (the gnome is 64 x 80 = 2 x 2.5 cells), so one art px is the same size on the gnome and on every creature.

## How the engine assembles it (fightengine.js `add`)
- Each part is an `<i>` with `background: url(sheet)`, `background-size: n*100% 200%`, `background-position: col/(n-1)*100% row*100%`, inset 0 over the actor box, `image-rendering: pixelated`. `transform-origin` = the pivot (as % of the frame).
- Two copies of the bone tree: the **ink tree (row 1) first, behind everything; then the paint tree (row 0)**. So one outline surrounds the whole figure and a part's own ring is hidden wherever another part's paint covers it. Consequence: a part painted ON TOP of another (a wing on a body, an arm on a coat) shows no outline there; draw an inner seam into its paint if it must read.
- Z order in each tree: roots in column order; inside a joint: its `under` children (column order), then its own picture, then its other children (column order). Children inherit their parent's transform (bones).
- Animation: Web Animations per part (rotate about the pivot, translate in figure units, scale sx/sy about the pivot), plus spring physics on sprung parts in rAF. The whole actor also moves/rotates per MOVES. Blink = `eyes` (or `eyeL`/`eyeR`) scaled in y about its pivot.
- If a slug has no rig row (or no sheet) the engine shows the still `mini-<slug>.png` instead.

## Constraints a redraw must keep (so no JS changes)
1. Same PNG size and mode; part count/order unchanged (smoke.js: `naturalWidth === cols * fw`).
2. Hard alpha; row 1 = ring of row 0 (or consistent ink), nothing outside a part's column.
3. Each part drawn **around its pivot** so the motion set makes sense: a leg hangs from its hip pivot to the ground row, a tail leaves its pivot in the spring's rest `dir`, segments chain pivot to pivot, `eyes` centred on its pivot (blink), frog eye bumps sit on their pivot (they squash down onto it), a wisp `body` rises from its bottom pivot, a snail/clam `shell` hinges on its pivot (charge claps it), a `head` with `HIDE` pose shrinks toward its pivot.
4. A child's pivot should lie on its parent's paint, or the joint opens up when it rotates (exception by design: the bullfrog's `fly`).
5. Under parts (`under:1`) are hidden behind the parent; they must stick out (wings above a bug's body, far legs offset, tails).
6. fightrigs.js is GENERATED: re-running `gen.lua ... game=1` overwrites every sheet. If the redraws ship, either gen.lua must skip redrawn slugs or the redraws become its source.

## Tests that read rigs
- `tools/fight/smoke.js` (via `game/fight_demo.html`): `FightEngine.validate()` lint (bones, parents drawn, archetype poses only name known parts, moves exist), 4 creatures x 12 scenarios, then EVERY rigged creature: sheet loads, width = cols x fw, enters, attacks, is hit, KO, no NaN transforms, fidgets.
- `tests/fight_scene.sh` + `tests/fight_scene.js`: the real fight page mounts and plays (one creature, whichever the test fight draws).
- `tests/manifests/*.txt` hold release hashes of every file, including rigs; `tests/build_update.sh` diffs against them to build update zips (a changed rig just becomes part of the next update, not a failure).
- Nothing in tests/ checks rig pixels, colours or palette.
Other readers of the gnome sheet only: `spit.php`, `fightdemo.js`, `tools/gnome_rig_parts.php`, `includes/gnome_rig.php`.
